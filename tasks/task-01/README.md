# Практическая работа 1

## Установка SSL-сертификата для nginx

### Цель работы

Получить практические навыки настройки защищённого HTTPS-соединения для веб-сервера nginx с использованием самоподписанного SSL-сертификата.

### Технические требования:

- Наличие интернет-соединения
- Наличие [Docker](https://docs.docker.com/desktop/) и [Docker Compose](https://docs.docker.com/compose/install/)
- Наличие [Wireshark](https://www.wireshark.org/)

### Ход работы:

1. Запустите контейнер с nginx посредством команды `docker compose up -d`.

2. Убедитесь в том, что веб-сервер доступен по HTTP.
Откройте в браузере `http://localhost`
Убедитесь, что nginx корректно раздаёт предоставленную статическую страницу.

3. Подключитесь к контейнеру посредством команды `docker exec -it nginx sh`.

4. Установите OpenSSL в контейнере nginx, используя пакетный менеджер apk.

5. Посредством [OpenSSL](https://docs.openssl.org/?utm_source=chatgpt.com) сгенерируйте закрытый ключ и самоподписанный сертификат в директории `/etc/nginx/ssl/` контейнера. При успешной генерации закрытый ключ и сертификат также появятся в директории `./certs` хостовой системе.

6. Сконфигурируйте nginx для работы с HTTPS
Для этого ознакомьтесь с документацией [nginx](https://nginx.org/ru/docs/http/configuring_https_servers.html) и внесите изменения в файл `/etc/nginx/conf.d/default.conf` внутри контейнера (соответствующий ему файл `./nginx/default.conf` в хостовой системе). 

7. Настройте nginx таким образом, чтобы обращения к веб-серверу по HTTP автоматически перенаправлялись на HTTPS. Для этого внесите изменения в конфигурационный файл согласно [документации](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html)

После внесения изменений проверьте конфигурацию посредством команды `nginx -t` и выполните примените изменения конфигурации nginx.

8. Проверьте корректность настройки HTTPS

Откройте в браузере `https://localhost`

Убедитесь, что веб-сервер корректно отвечает по HTTPS и статическая страница продолжает отображаться.

Так как в работе используется самоподписанный сертификат, браузер может предупредить о том, что сертификат не является доверенным.

Изучите информацию о сертификате, которую предоставляет браузер.

9. Выполните исследование трафика в Wireshark

Запустите Wireshark и начните захват трафика.

В браузере выполните обращение к настроенному веб-серверу по HTTPS.
Используя возможности фильтрации Wireshark, найдите пакеты, относящиеся к TLS-соединению.
Самостоятельно определите подходящий фильтр Wireshark для поиска TLS-трафика и/или соединений с портом 443.
Исследуйте начало соединения и найдите сообщения TLS Handshake.

Обратите внимание на:
- Client Hello;
- Server Hello;
- сертификат сервера;
- последующий зашифрованный обмен данными.

После установки защищённого соединения найдите пакеты, содержащие зашифрованные данные приложения.
Убедитесь, что содержимое HTTP-запроса и HTTP-ответа не отображается в Wireshark в открытом виде.

Сравните HTTP и HTTPS соединения. Убедитесь, что при передаче данных по HTTP содержимое запроса может быть прочитано непосредственно из сетевого трафика, тогда как при использовании HTTPS содержимое передаваемых данных не отображается в открытом виде.
